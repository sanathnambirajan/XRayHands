X-Ray Hands: oral exam guide

Group 07 · 6172 Immersive Analytics · WiSe 2026/27 · Mithulram Gunasekaran, Sanath Nambirajan

1. The project in 30 seconds

Problem: engineers check X-ray CT scans of metal parts for hidden defects (pores, cracks). Normally they scroll through hundreds of 2D slices with a mouse.

Our solution: the scanned part floats in front of you in your real room (Meta Quest 3, passthrough). You explore it with bare hands only, with no menus and no controllers. You cut it with a flat palm, peel it with two palms, probe it with a finger (with sound), look through an X-ray lens, and pinch and pull a pore so all pores fly out into a linked 3D scatter plot.

Challenge: C2 "Beyond Point-and-Click": natural 3D interaction instead of 2D menus.

3. How the pieces fit together

CT scan ──(Python, tools/)──► volume_u8.raw + labels_u16.raw + features.csv + meta.json │ (loaded from StreamingAssets) ▼ Real hands (Quest) ┐ ├─► IHandSource ─► HandFrame ─► GestureRecognizer ─► InteractionModeController ─► Tool Keyboard + mouse ┘ (26 joints) (detectors + (one main tool at a time) │ hysteresis) ▼ VolumeRenderer (shader) ◄────── SelectionModel ──────► DefectChart3D (3D chart) Everything is created and connected in App/Bootstrap.cs ("composition root").

In plain words: Python prepares the data once. In the app, hand data comes in, gestures are recognised, the controller picks one tool, and the tool changes what the shader shows or what is selected. The selection is shared, so the part and the chart always agree.

5. Each part explained simply

a) Data pipeline (Python, tools/)

  • Crop: the full NIST scan (900 × 1010 × 984 voxels) doesn't fit in 16 GB RAM with all masks, so we take the central 640³ cube (1.57 mm).
  • Denoise: a 3×3×3 median filter, the same as NIST's own pipeline.
  • Threshold, ISO50: the surface sits halfway between the air and metal grey values. We tried Otsu first, but it needs two peaks in the histogram. Pores are under 1 % of the voxels, so Otsu split the metal's noise and found 103,094 fake pores. ISO50 gave 2,910.
  • Pore = air enclosed by metal: 3D hole filling. Air that touches the outside is not a pore.
  • Measure first, then shrink: pores are only a few voxels big. Shrinking first would delete them.

b) Volume rendering (XRayVolume.shader)

  • Ray marching: for every pixel, send a ray from the eye through the cube, take small steps, add up colour and opacity front to back, and stop at 97 % opacity.
  • Speed-ups for the Quest:
    • The gradient is stored in the texture, so each step needs 1 read instead of 7.
    • Empty-space skipping: 8³ blocks remember their min/max value, so the ray jumps over empty air.
    • Jitter: each ray starts at a slightly different offset, which removes stripe artefacts without needing more steps.
  • Cut: the ray starts at the cut plane. If it starts inside metal, we show the grey value directly, which is why the face looks like a real CT slice.
  • Peel: metal becomes nearly transparent, but the edges stay visible (a "rim" term), so it looks like glass.
  • Lens: if the pixel's ray passes through the finger ring, that ray uses the peeled look.

c) Hands and gestures (Input/, Gestures/)

  • One hand model, two sources: real Quest tracking or keyboard/mouse. The gesture code is identical, so testing in the editor tests the real code.
  • Detectors give a confidence from 0 to 1. Each rule is a soft ramp, and the gesture takes the minimum of its rules (a "fuzzy AND"). Example, flat palm: all four finger curls below 0.25, palm inside the part (+5 cm), held 150 ms.
  • Hysteresis: a gesture turns on at confidence 0.95 and only turns off at 0.05. A hand hovering near a threshold therefore doesn't flicker on and off.
  • Why rules and not machine learning? The poses are simple and geometric. Rules need no training data, are easy to explain, can be unit-tested, and every threshold is in one file.

d) Tools (Interaction/)

  • Each tool follows the same 4 steps: CanStart → Begin → Tick (every frame) → End.
  • Grab remembers the hand-to-part offset, so the part doesn't jump. Scale zooms around the point between your hands.
  • Cut: the near half (towards your head) is removed. Twisting the wrist 45° doubles or halves the contrast.
  • Peel: palm distance 8–45 cm maps to 0–100 %.
  • Extract: pinch a pore and pull 12 cm, and the chart animation starts.

e) Chart and linking (Analytics/)

  • Axes: pore size (log volume) × sphericity (roundness) × build height. Dot size grows with the real pore size; colour = pore type.
  • All dots are one mesh, so they cost a single draw call on the Quest.
  • Fly-out animation: each pore travels on a curved arc (a Bézier curve), with staggered start times so the eye can follow.
  • SelectionModel is the single "source of truth". The part, chart, link line and tooltip just listen to it, which is why linking works in both directions.

f) Sound (Audio/ProbeSonifier.cs)

  • The sound is generated live in OnAudioFilterRead, on an audio source at the fingertip, so it comes from where your finger is.
  • Pitch follows density over 2 octaves. Clicks get faster near a pore, like a Geiger counter, and each click also pulses a ring, so it works without sound too.

6. Likely oral exam questions, with short answers

Q1. Why is this an immersive analytics project and not just a 3D viewer?Because users analyse data: they find pores, compare them in a linked chart, and check our detection against ground truth. And they do it with natural 3D interaction, not just by looking.
Q2. Why is 3D better than 2D slices here?A CT scan is 3D already. You see where pores cluster without rebuilding it in your head, you can cut at any angle (not only 3 fixed axes), and the chart sits next to the part, so the link is visible.
Q3. What data did you use, and why?A: a NIST 3D-printed cobalt-chrome sample, because it has real pores and an official reference segmentation, so we can measure how good our detection is. B: the Enigma rotors scanned by Fraunhofer IIS/EZRT, to show the tool works on a different object.
Q4. How do you find the pores?Denoise, then the ISO50 threshold (halfway between air and metal), then "air enclosed by metal" via 3D hole filling, then connected components give each pore an ID. Code: preprocess.py, segment.py.
Q5. Why not Otsu thresholding?Otsu needs two peaks in the histogram. Pores are under 1 % of voxels, so there's only one peak, and Otsu found 103,094 fake pores. ISO50 is the standard in industrial CT.
Q6. How good is your segmentation?Precision 0.90 (90 % of what we find is real), recall 0.75 (we find 75 % of the real pores), IoU 0.59. We miss small, faint pores because we use one global threshold, while NIST used a local one. The app shows this honestly in the ground-truth view (key T).
Q7. What are precision, recall and IoU?Precision = TP / (TP + FP). Recall = TP / (TP + FN). IoU = overlap of our pore voxels and theirs, divided by their union.
Q8. What is sphericity, and why is it 1.0 for many small pores?How close a shape is to a sphere (1 = perfect sphere), computed from volume and surface area. Pores of 8–30 voxels are too small to measure their surface properly, so the value saturates. We say this openly.
Q9. How does volume rendering work?Ray marching: per pixel, step through the volume, look up colour and opacity for each grey value (the transfer function), add them up front to back, and stop when nearly opaque. It's done per eye, so stereo is correct.
Q10. How did you make it fast enough for a Quest?Empty-space skipping, gradient stored in the texture, early stop at 97 %, jitter instead of more steps, and quality tiers of 96/160/256 steps with opacity correction so all tiers look alike. Note: we haven't measured the frame rate on a Quest yet.
Q11. How does the cut make a real CT slice?The ray starts at the plane. If the first sample is metal, it outputs that grey value opaquely, so the face shows the measured data, not a made-up colour.
Q12. How do you recognise gestures?With geometric rules on finger curls, palm normals and pinch distance. Each rule is a soft ramp, the minimum gives the confidence, and hysteresis keeps it stable. Code: Detectors.cs, Ramp.cs, GestureState.cs.
Q13. What is hysteresis, and why do you need it?Different thresholds for turning on (0.95) and off (0.05), plus hold times. Real hand tracking is noisy, and without it a gesture would flicker on and off.
Q14. What if two gestures are true at the same time?The recognizer reports everything; InteractionModeController decides. Two-hand tools are checked first, and a running tool keeps control until its own gesture ends. One bug we fixed: a running cut used to block the peel gesture.
Q15. How is the palm normal computed?The cross product of "across the knuckles" and "along the hand". The order is flipped for the left hand, otherwise its normal points out of the back of the hand. A unit test checks both hands.
Q16. How does linked selection work?One SelectionModel holds the selected pore IDs. The shader, chart, link line and tooltip all listen to it. Selecting in the part or in the chart changes the same model, so both views update.
Q17. What do the chart axes mean?x = pore size (log volume), y = sphericity, z = build height in the sample. Build height matters because the part is 3D-printed layer by layer. Visible trend: bigger pores are less round.
Q18. What do the pore colours mean?Yellow = gas pore (round), orange = lack of fusion (irregular, unmelted powder), red = crack-like. In ground-truth mode: blue = correct, orange = false, pink = missed.
Q19. Why sound?It gives density information without looking away, and it tells you when you're near a pore. It's multisensory analytics, which the challenge asks for. Every click also has a visual ring, so it isn't sound-only.
Q20. Is the probe value a real density?No. CT grey values are uncalibrated X-ray attenuation, so we show the raw grey value and the material class, and label it that way.
Q21. How did you test without a headset?Simulated hands from keyboard and mouse build full 26-joint hands, so the real gesture code runs. A script also injects hand poses to take screenshots, plus 43 Unity tests and 28 Python tests.
Q22. What bugs did you find?A precision pinch was detected as a grab; a running cut blocked the two-hand peel; the lens threshold was too low for this metal (0.6 → 0.92); labels were drawn behind the volume. All are fixed, with tests where possible.
Q23. What are the limitations?Not tested on a real Quest yet, no user study yet, only one global threshold for segmentation, small-pore sphericity isn't meaningful, and some tools aren't tested end to end.
Q24. What would you do next?Test in the lab with real hands and tune the thresholds; measure the frame rate; add the specimen shelf and slice cards; run a small user study against a 2D slice viewer.
Q25. How would you evaluate it?A small study where users find and compare defects with X-Ray Hands vs a 2D slice viewer. Measure time, errors and a usability questionnaire (e.g. SUS), plus comments.
